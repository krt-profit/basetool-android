Handoff — OssLicensesScreen
  • Quelle: res/raw/oss_licenses.json — Licensee-Report der Build-Variante (Task OssLicensesResource). Off-main parsen; Reihenfolge deterministisch: Gruppen alphabetisch nach Lizenzname, Artefakte alphabetisch
  • Sticky-Header: JA — LazyColumn stickyHeader() je Gruppe; gepinnt identisch zum ruhenden Header (opak #1C1C1C, 2-dp-Orange-Regel, keine Elevation)
  • Koordinate = EIN String group:artifact:version — Version in derselben Zeile; Umbruch break-all ohne hängenden Einzug (bis ~57 Zeichen einzeilig bei 13 sp / 412 dp — kotlinx-coroutines-android:1.10.2 passt; adaptive-navigation:1.3.0 mit 62 Zeichen bricht auf Zeile 2). Zeilen nicht interaktiv, min. 40 dp, 13 sp / 1.5
  • Gruppe mit 1 Artefakt: kein Sonderfall — gleicher Header inkl. „1 Artefakt" (hier: BSD-3-Clause)
  • Dual-Lizenz: Artefakt erscheint unter JEDER Lizenz (hier illustrativ: javax.annotation-api unter CDDL 1.1 UND GPL 2.0 CPE). Heutiger Prod-Graph hat exakt 2 Gruppen — licensee-Gate erlaubt nur Apache-2.0 + BSD-3-Clause
  • Neue Lizenz ⇒ licensee allow() + OssLicense-Eintrag (Name + kanonische URL); OssLicensesTest erzwingt das Paar
  • Leer-Zustand unerreichbar (Graph nie leer); Report mit 0 Artefakten ⇒ Fehlerzustand (Artboard 5). Keine Suche, kein Filter — bewusst
  • Rahmentext: NÖTIG — erklärt Build-Bezug & exakte Versionen (2 Sätze + Meta-Zeile, Artboard 1)
